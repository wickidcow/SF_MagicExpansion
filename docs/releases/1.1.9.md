MagicExpansion 1.1.9 adds automatic coexistence with dedicated fishing plugins.

- With `Fish.Compatibility.mode: AUTO` (the default), MagicExpansion leaves fishing to enabled PyroFishing/PyroFishingPro, BetterFish/BetterFishing, EvenMoreFish, CustomFishing or UltimateFishing plugins. Without one of these plugins, its original fishing system runs normally.
- Both regular and Water Cloud rods use the same compatibility decision. When paused, MagicExpansion does not replace catches, consume its bait, add rewards, change fishing XP or trigger catch effects.
- Plugin enable/disable changes are detected automatically. Add other plugin names under `Fish.Compatibility.additional-plugins`, or select `COMPATIBILITY` to leave all fishing events untouched. `FULL` explicitly enables MagicExpansion catch effects and can conflict with another fishing plugin.
- Added `/magicexpansion fishing` for status and `/magicexpansion reload fishing` to apply compatibility configuration changes.
- Cancelled, missing and removed catches are ignored. Normal pending catch entities still reach the original rod handlers.
- Existing rods, fish, item/research IDs, typed persistent data, recipes, guides, machines and shop records are retained. Other plugins' fish are not converted into MagicExpansion fish. Dedicated fishing plugins decide which rods they accept.

Install the raw **SF_MagicExpansion1.1.9.jar** asset and use a full server restart. The distributable is built against Paper 1.21.11 and checksum-verified Slimefun Legacy 4.1.61, with Java 21 bytecode. Java 25 is used for builds and tests.

Validation includes 97 passing automated tests (21 fishing cases), Paper 1.21.11/26.2/26.3 compilation, and tests against published Slimefun Legacy 4.1.68. The baseline-built candidate passed binary linkage checks against 4.1.68 and two isolated Paper 26.3 build 143 server boots, including both actual rod handlers, cancelled and pending catches, bait/XP preservation, cargo, sword and shop regressions.

Named-plugin detection uses MockBukkit tests. The real-Paper checks use a no-network player facade. Actual PyroFishing/BetterFish JAR combinations, live-client fishing, arbitrary plugin combinations, historical worlds and Folia region behavior are not certified. Inherited deprecated compatibility APIs remain visible in build output.
