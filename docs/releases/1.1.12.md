# MagicExpansion 1.1.12 — Black Market cycle diagnostics (draft candidate)

This build preserves MagicExpansion 1.1.11 fishing announcement privacy and 1.1.10 restart-safe Black Market purchase receipts.

## Operator diagnostics

- `/magicexpansion blackmarket status` requires OP and reads only the cycle marker; it reports whether the live and disk cycles match, are semantically identical with altered file bytes, differ in cycle ID/time, or are unreadable/missing.
- It prints trading lock state, safely decoded cycle IDs/start timestamps, and an in-memory count of locked player records. It does not expose players' purchases, item contents, or credentials.
- It does not perform an automatic migration, repair, reset, refresh, or transaction. The original fail-closed purchase path is unchanged.
- Regression tests cover missing, unreadable, same-cycle rewrite and different-cycle mismatches. Existing market transaction and fishing tests remain enabled.

## Upgrade

1. Keep existing `plugins/magicexpansion/black_market/` untouched and back it up, including `cycle.yml` and `players/`.
2. Replace the older JAR with the **single** versioned `SF_MagicExpansion1.1.12.jar` only after CI, checksum and staging verification; do not install two plugin JARs with the same plugin name.
3. Check `/magicexpansion blackmarket status`. A mismatch does not clear on demand. Investigate the real file and purchase ledger history before enabling trading.
4. Keep all existing configs and item IDs; this release changes no persistent schema, offer prices, rewards, fishing behavior, loot or public chat defaults.

Read `docs/black-market-cycle-diagnostics.md` for lock semantics and a recovery checklist.

**Release gate:** This is a draft version, not a publication, and the original affected production state has not been examined. Do not publish or deploy it until a clean CI build and an old-world read-only test prove expected behavior.
