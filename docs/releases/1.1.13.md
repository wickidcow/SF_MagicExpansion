# MagicExpansion 1.1.13 — Black Market receipt and restart safety

This is a targeted safety update on top of 1.1.12 diagnostics. It preserves fishing announcement privacy, existing items and research IDs, recipes, costs, rewards, the four-hour market rotation and one-purchase-per-slot behavior.

## Safeguards

- A missing `cycle.yml` no longer creates a fresh cycle when player receipts, backups, temporary files or other existing market state remain. A genuinely new, empty installation still initializes normally.
- Unreadable, empty, disappearing or symbolic-link state files are not interpreted as a clean purchase history. Trading and writes are refused when state cannot be trusted.
- A failed initialization invalidates the old in-memory session, preventing stale authorization from surviving a later file restoration.
- Refresh requests must match the current cycle identity and start time. Stale requests cannot replace a newer cycle.
- The existing exact-byte conflict check and save-before-reward receipt ordering remain enabled. The status command remains read-only.

## Safe upgrade

Stop the server and retain a complete backup, including `plugins/magicexpansion/black_market/cycle.yml`, all files in `black_market/players/`, the previous plugin JAR and dependent Slimefun data. Replace only the old MagicExpansion JAR with one officially published `SF_MagicExpansion1.1.13.jar`; do not load duplicate versions. Start normally rather than using `/reload`.

Run `/magicexpansion blackmarket status`. This update does not automatically repair or unlock an existing mismatch. Do not delete receipts, move a live cycle file aside, reset purchase limits or reroll offers to suppress a lock. Investigate the stopped-server state and backup history first. Missing-cycle protection may deliberately keep an already damaged market locked.

## Validation boundary

Before assigning 1.1.13, the unchanged Java logic passed 146 tests in 14 suites (including 40 Black Market tests), the 45-addon build, and installed-addon store checks over four fresh JVMs on each of Paper 1.21.11, Paper 26.2, Paper 26.3 and experimental Purpur 26.3. Those checks preserved synthetic purchase/reveal receipts, offers, amounts and custom PDC metadata, exercised external/missing cycle refusal and allowed legitimate rotation. Native Networks/Fluffy item conservation also passed on Paper 26.3.

The versioned candidate is separately revalidated before release; authoritative exact-head and artifact-hash evidence is maintained in SF_MagicExpansion PR #18 and Slimefun-Legacy PR #386. A source branch, draft PR or Actions artifact is not an official release. Compilation and synthetic native tests do not prove live-client behavior, power-loss atomicity, every historical world or a diagnosis of Albion's original externally changed cycle. No test probe is included in the distributable JAR.
